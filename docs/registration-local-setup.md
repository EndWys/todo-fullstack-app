# Проверка регистрации в локальном окружении

## Запуск

1. Убедитесь, что backend имеет локально настроенную `ConnectionStrings:TodoApp` и к выбранной БД уже применена миграция. Не сохраняйте строку подключения в Git. Эти шаги не применяют миграций автоматически.
2. Из корня репозитория запустите API:

   ```powershell
   dotnet run --project backend/src/TodoApp.Api --launch-profile https
   ```

3. В другом терминале перейдите в `frontend` и выполните `npm start`.
4. Откройте `http://localhost:4200/register` (или адрес, показанный Angular CLI).

`frontend/src/proxy.conf.json` направляет `/api/**` на `https://localhost:7127`, как в HTTPS launch profile API. При изменении порта обновите proxy и перезапустите Angular dev server. `secure: false` допускает локальный dev-сертификат только на участке proxy → API; это не настройка production. Через удалённое окружение пароли передавайте только по HTTPS.

## Ручной сценарий

- Используйте вымышленные тестовые данные и уникальный email. Реальная отправка создаёт запись в выбранной backend-базе.
- Введите пароль из 15–256 Unicode code points. Нажмите **Create account**.
- В браузерной вкладке Network ожидается один `POST /api/auth/register`, ответ `201` с `id`/`email`, без пароля. Не публикуйте содержимое запроса или HAR: они содержат пароль.
- UI показывает **Account created … You are not signed in**, поле пароля очищается. Сессия не создаётся.
- Повторная регистрация этого email должна вернуть `409` и ошибку возле email.
- Для проверки общего сообщения можно остановить API и отправить валидную форму. Ошибка связи не доказывает, что предшествующий запрос не создал аккаунт; автоматических повторов нет.

Для автоматизированных сценариев с БД используйте отдельную `TodoAppTest`, а не рабочую базу.

## Автоматические проверки frontend

Из `frontend`:

```powershell
npm run build
npm test -- --watch=false
```

HTTP-тесты используют Angular `HttpTestingController`: они не требуют SQL Server, не отправляют запросы в настоящую API и не заменяют ручную проверку цепочки UI → API → БД.
